# Логи и рабочие данные

Из Telegram-бота перенесены принципы: единый формат события, идентификатор запуска, разделение по дате и уровню, безопасные поля, отдельная папка рабочих данных и отчёты миграций. Python-код, данные и сложный runtime бота не копировались.

Образцы, прочитанные только как справка: `app/core/logging/layout.py`, `model.py`, `redaction.py` и `app/core/persistence/contracts.py` в Telegram-Bot.

## Событие

`schemaVersion, timestamp, level, area, event, runId, fields`. Время — ISO UTC, папка — выбранный часовой пояс. Коды событий стабильные, например habit.completed и focus.paused. Тексты интерфейса не являются кодами логов.

В fields разрешены только заранее выбранные диагностические поля. Запрещены почта, токены, пароли, названия привычек, тело запроса и сырое исключение. Даже отладка не снимает это правило.

Сбой записи вызывает обработчик деградации; нормальный обработчик должен увеличивать счётчик и печатать безопасную служебную строку без исключения наружу. Сбой sink не должен менять успешность действия пользователя.

## Файлы

`storage/logs/<дд.мм.гггг>/<уровень>/<runId>.jsonl` и общий уровень all. Файл ограничен 5 МиБ, до трёх архивов на запуск. Записи одного экземпляра идут последовательно. runId уникален для процесса.

Очистка старых папок вызывается отдельно владельцем логов; проверяет реальный путь и не заходит в ссылки. Начальный срок — 14 дней. Остальные рабочие данные описаны в `storage/README.md`.

## Телефон

NodeFileSink нельзя включать в мобильную сборку. Для телефона в HZ-02 нужен отдельный ограниченный адаптер в песочнице Expo с ротацией и счётчиком потерянных событий. Передача диагностики на сервер по умолчанию выключена. Выгрузка пользователем — явное действие.

Отчёт об ошибке не должен превращаться в скрытый сбор личных привычек. Логи — вспомогательная диагностика, а не история выполнений и не резервная копия.
