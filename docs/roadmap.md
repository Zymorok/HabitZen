# План реализации

Общий объём включает весь HabitZen из задания, три его бонуса и все согласованные экраны. HZ-01 подготовил основу. По уточнению владельца текущий HZ-02 ограничен кадром 01: рабочее знакомство, темы, языки и сценарий разрешений. Вход и начало работы отключены.

| Этап                       | Результат для пользователя                                                    | Условие завершения                                                                |
| -------------------------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| HZ-01 Основа               | Понятное устройство проекта и проверяемые общие правила                       | Документы, модули, схема, логи, локализация, проверки основы                      |
| HZ-02 Облик и приложение   | Запускается приложение в стиле макета, работает навигация, тема и выбор языка | Expo Doctor, сборка, реальные экраны с честными состояниями, проверка трёх языков |

Статус на 18.10.2026: HZ-01, HZ-02 (с живым миром HZ-02b) и HZ-03 выполнены. HZ-03 подключил настоящий локальный Supabase: вход, регистрацию, восстановление пароля, выход и команды привычек (создать, изменить, архив) с проверкой владельца, версии и requestId. HZ-04 выполнен 19.10.2026: «План на день» по кадрам 02–05 с нижним меню, удержание 1,2 с с вибрацией, «Отлично!», отмена отметки, «Сегодня отдых» свайпом и через меню, изменение и архив привычки, серия дней по правилам ядра. Вкладки «Фокус» и «Прогресс» пока честно сообщают, что появятся в HZ-05; профиль — часть кадра 12.

HZ-02 делает подготовленный интерфейс, HZ-03–06 подключают реальное поведение. Демонстрационные данные имеют отдельный режим и не маскируют ошибки настоящего сервера.

## Отдельные будущие направления

Полностью автономная работа без сети с разрешением конфликтов, удалённые push, общий доступ к привычкам, платные планы, административная панель и внешний сервер в текущее задание не добавляются. Границы модулей позволяют развивать их позже.

## Что не терять между этапами

Журнал решений — docs/decisions.md. Проверки этапа — docs/verification.md и storage/reports. Требования — docs/requirements.md. Макет и его описание хранятся в репозитории. Готовность отмечается по фактам, а не по числу созданных файлов.
